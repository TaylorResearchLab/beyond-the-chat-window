# Findings from use

## Collaboration and continuity

The frozen record supported three qualitative observations about task performance and continuity. GPT and Claude each led tasks and reviewed the other's work, and both produced contributions the User accepted in each role. The User did not identify one platform as consistently better across task types. This was a judgment within one case, not a controlled comparison.

Corrections occurred in both directions. Each platform identified errors in the other's work and revised some of its own claims. Courteous exchanges included criticism, retractions, repairs, and adjudication; courteous wording did not imply agreement. Because assignments and exposure were not controlled, these observations do not establish independence or a benefit from provider diversity.

Handoffs, accepted decisions, and links to current files allowed new sessions to resume work without reconstructing the project solely from old chats. That continuity depended on active maintenance: the User continued to route reviews, identify governing state, resolve competing proposals, and request missing records. The observation supports including those duties in adoption instructions, not assuming that a structured workspace performs them automatically.

## Available context was not always applied

A session could complete a local task while overlooking an upstream decision or a parallel result that changed its interpretation. For example, code could be revised from the supplied files without retrieving a notebook that fixed the canonical input definition or a review that changed the acceptance criteria. The problem became visible when the User identified the missing dependency and directed the session to the relevant record.

The User consequently maintained a map of dependencies among hypotheses, data descriptions, code, validation results, and writing decisions. This did not require retaining every detail unaided; the shared record served as external memory. The additional task was deciding which records had to be retrieved together and when new evidence required a change in direction. These observations motivated selective context assembly and project reorientation in the implementation guide. They do not establish that broader context loading necessarily impairs performance or that future systems could not perform this integration.

## Support for FAIR principles

The workflow provided documented but incomplete support for FAIR-oriented practice.

| FAIR dimension | Documented support | Evidence of incomplete support |
| --- | --- | --- |
| **Findable** | Structured fields, accepted-state pages, handoffs, repository links, and commit identifiers exposed the location of current work. | Some decisions remained only in chat. Misplaced records could be reachable by URL yet absent from database queries. Temporary review fields did not preserve complete review history. |
| **Accessible** | Records identified artifact locations and access conditions; permissioned workspaces allowed intended participants to retrieve shared material. | Files confined to one platform's chat or sandbox required deliberate transfer. The tested Notion configuration did not provide a general bulk-export or cross-database analysis path. |
| **Interoperable** | Repeated machine-readable fields and stable identifiers connected records, revisions, configurations, and outputs across the participating platforms. | Differently structured logs could not be pooled in the standardized corpus. Exchange remained operational within the workflow, depended on proprietary services, and did not establish full semantic interoperability. |
| **Reusable** | Records could preserve rationale, code, commands, inputs, outputs, environment information, limitations, review, citation checks, and supersession. | Some omitted the code or query behind a result, used invalid checksums, or referred to untransferred files. Repository metadata did not distinguish agent-initiated from manual actions under the same credentials. |

The strongest support occurred when claims were linked to exact revisions and execution evidence. The weakest support occurred when work remained in chat or omitted the materials needed to check it. Structured storage alone did not make the work or its products FAIR.
