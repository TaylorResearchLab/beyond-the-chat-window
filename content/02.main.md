# Introduction

Scientific work rarely fits inside one chat session. A project may continue for months, use several repositories, depend on data that cannot leave a protected computing environment, and involve more than one AI platform. Chat interfaces do not reliably preserve the current project state, the reasons behind decisions, or the identity of the files and code that produced a result.

Many multi-agent frameworks address this problem by automating communication among model instances within a shared orchestration system [@arxiv:2308.08155; @arxiv:2308.00352; @arxiv:2307.07924]. This study examines a different arrangement. GPT and Claude did not communicate directly. A human investigator routed work between them through a shared Notion record and retained authority over scope, private data, final execution, acceptance, merge, and release. I refer to this human investigator as the User throughout the paper.

The User was not an occasional approval step. The User remained part of the process from question formulation and task assignment through evidence review, dispute resolution, and release. The workflow was therefore human-governed and User-mediated rather than autonomous.

The objectives were to describe the workflow, explain its governance and evidence rules, characterize a frozen retrospective record of its use, and report both useful collaboration patterns and operational failures. FAIR principles informed the design of the shared record [@doi:10.1038/sdata.2016.18]. This is a descriptive single-user study. It does not test causal benefit, compare model performance, or establish superiority over other collaboration methods.
