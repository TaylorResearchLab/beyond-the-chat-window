# Introduction

This work aims to help scientists adopt collaborative AI while retaining intellectual and process control of their research and maintaining a rigorous scientific record that supports reproducibility. The human investigator, termed the User, directs the scientific process. The workflow connects AI contributions to documented decisions, methods, evidence, and revisions so that work can be examined, reproduced, and continued across sessions.

Scientific work is difficult to execute and track inside isolated chat sessions. A project may continue for months, span many conversations, draw on several repositories, and depend on a computing environment outside the AI platform. Research also proceeds through linked hypotheses and parallel workstreams: data preparation, code development, validation, interpretation, and writing may advance at different rates. The practical problem is how to preserve the accepted project state and reconnect each contribution to the evidence, files, and decisions that govern it. These requirements also matter when AI-assisted work is incorporated into research records intended to support Findable, Accessible, Interoperable, and Reusable (FAIR) practices [@doi:10.1038/sdata.2016.18].

The main text explains the workflow's structure and how to establish a project, assign a bounded task, obtain review, accept a result, and hand work to a new session. Supplementary Note S1 provides the detailed work contract, setup guide, schemas, and templates. A development-stage Skill packages participant instructions and supporting reference files in the accompanying repository. These materials are intended as an adaptable starting point, not as a tested optimum or a substitute for scientific judgment.

The workflow developed through one investigator's use of ChatGPT, referred to here as GPT, and Claude. The assistants communicated asynchronously through a structured Notion Collaboration Log rather than a direct message channel. GitHub held versioned files, and final execution took place in User-controlled computing environments. The investigator prompted each participant to read the relevant records and act. When the recorded state was sufficient, a short instruction such as "Check the log" could initiate the next work unit.

Using a second provider was intended to introduce another perspective on code, evidence, and interpretation. It did not guarantee independent reasoning or uncorrelated errors. A second session from the same provider is also a possible adaptation, but the study did not compare those arrangements. Likewise, the workflow was not an autonomous system with occasional approval. Human-AI taxonomies distinguish mandatory human approval from autonomous systems that escalate when uncertain [@arxiv:2507.14034]. Here, the researcher actively directed assignments and integrated results across changing scientific questions.

The contribution has two parts: a specified workflow with practical adoption materials, and a retrospective account that documents its use and the failures that informed its development. The latter comprises a frozen record from one investigator and a separate manuscript-production case. It supports description of collaboration patterns, operational constraints, and FAIR-oriented record keeping. It does not establish causal benefit, comparative platform performance, or general usability. The following sections distinguish the current implementation guidance from the historical practices actually represented in that record.
